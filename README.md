# dsh-qq

将 QQ 接入 DeepSeek Harness（DSH）：在私聊、群聊和 QQ 频道中与模型对话、收发附件、切换人设、管理会话和处理审批。同时包含 **官方 QQBot** 与 **个人 QQ / OneBot 11（如 NapCat）**，两条线路可单独或同时使用。

## 功能

- **工作与聊天模式**：每个对话分别保留两套会话和人设。工作模式处理任务；聊天模式用短句、自然等待和图文组合接话，限制可执行工具。
- **人设与群聊**：按群或私聊绑定人设，设置呼唤昵称、活跃档位和最多 40 张精选表情；支持明确呼唤、短时间续聊和参与判断。
- **表情图库**：收集、识别、收藏、搜索和管理图片；两行分页、描述编辑、缺描述筛选、批量补全和重新识别，按场景优先选人设精选。
- **图文预演**：试用未保存的人设草稿，可上传图片或选择已有表情，预览短句和选图顺序，保存浏览器本地试聊样例。
- **远程控制**：切换模型、推理强度、会话和模式，停止生成，接收工具审批与主动通知。
- **群记忆与提醒**：近期群聊上下文、群专属约定/梗笔记、一次性和每日提醒；可暂停主动互动、关闭某个群的表情。
- **控制台与诊断**：连接状态、身份与授权、模型用量，以及入站、排队、生成、发送结果和未接话原因。

## 安装与更新

需要 Node.js 22 或以上，以及已能正常使用模型的 DSH `web` profile。按需要准备 QQBot 应用，或已经安装并登录的 NapCat；**个人线路不需要 QQBot AppID**。

```bash
# 从 GitHub 安装或更新
dsh plugin --profile web add github:qiufengqing06/dsh-qq

# 或从本地源码目录安装
dsh plugin --profile web add /path/to/dsh-qq

# 卸载
dsh plugin --profile web remove dsh-qq
```

也可以在 DSH Web「插件」页填写 `github:qiufengqing06/dsh-qq` 安装。本项目不通过 npm 包名安装。

安装或更新代码后，重新加载插件或重启 DSH，再刷新页面。打开侧边栏「QQ 控制台」，或访问 DSH Web 地址下的 `/dsh-qq`，例如 `http://127.0.0.1:3080/dsh-qq`。页面显示新版本号不代表旧后端代码已重新加载。

## 接入线路

### 个人 QQ：OneBot 11 / NapCat

1. 按 [NapCat 官方文档](https://doc.napneko.icu/)安装并登录 QQ。本插件只提供 OneBot 客户端，不安装或分发 NapCat、QQ 客户端。
2. 在 NapCat 网络配置中启用 **WebSocket 服务端（正向 WS）**，例如 `ws://127.0.0.1:3001`，消息格式使用 `array`，设置访问 token。
3. 在 QQ 控制台的配置中启用个人 QQ 线路，在「配置 → 连接与群聊」填写同一 WebSocket 地址；在「登录与凭据 → 个人号 access_token」保存 token，凭据引用为 `ONEBOT_ACCESS_TOKEN`。
4. 保存后检查连接状态；必要时点击「重新连接」或执行 `/qq-reconnect`。私聊直接发消息，群里先用 @ 测试。

对应插件配置字段如下。修改已安装插件的配置即可，不要重复插入插件行：

```yaml
transport: onebot
onebot:
  wsUrl: ws://127.0.0.1:3001
  sendRateLimitMs: 300
mentionRequired: true
freeReplyGroups: []
```

已有 `transports` 列表时，它优先于 `transport`。旧配置中非空的 `onebot.accessToken` 优先于凭据服务；改用页面管理 token 时应清除此旧项。

默认只允许连接回环或私网地址；连接公网端点需显式设置 `onebot.allowRemote: true`。容器或不同机器部署时，填写 DSH 所在环境可访问的地址。

NapCat 启停和二维码是**可选宿主集成**：在 YAML 配置 `napcat.ctlScript`、`napcat.qrFile` 和 `napcat.webuiUrl`。控制脚本以 `bash <脚本> start|stop|restart` 调用；二维码需指定实际文件。未配置时在 NapCat 自己的 WebUI 管理即可。宿主面板基于本机探测，不代表远程 NapCat 的完整状态。

同机文件读取可用 `napcat.fileRoot` 指定允许目录。远程部署时，NapCat 本地文件路径不一定能被 DSH 访问，文件传输需后端提供可访问地址。

### 官方 QQBot

在 [QQ 开放平台](https://q.qq.com/)准备机器人应用及所需事件权限，然后任选一种方式：

- 控制台「登录与凭据」点击「扫码登录」，打开生成的绑定链接，用手机 QQ 完成平台绑定；也可在 DSH 会话中执行 `/qq-login`。
- 手动填写 AppID、AppSecret，或在 DSH 凭据服务配置 `QQ_APP_ID`、`QQ_CLIENT_SECRET`。

保存后检查连接状态。群聊、频道、主动消息等能力以应用实际获批权限及平台推送事件为准；插件无法处理平台未推送的普通群消息。密钥只填在配置入口，不要发送到聊天中。

### 两条线路同时运行

```yaml
transports:
  - kind: qqbot
  - kind: onebot
onebot:
  wsUrl: ws://127.0.0.1:3001
```

两条线路分别使用自己的身份、授权和对话，回复回到来源线路。未配置 `transports` 时沿用单线路 `transport`。不需要某条线路时设置该项 `enabled: false`。

## 人设与自然群聊

1. 在目标 QQ 对话发送 `/qq-mode chat`，或在控制台切换到「聊天」。
2. 在「会话提示词 → 人设库」新建或编辑人设，填写正文、呼唤昵称、默认活跃档位，选择精选表情并保存。
3. 在「按对话绑定」中绑定目标人设。工作与聊天模式分别绑定，也可用 `/qq-persona use <id>` 切换当前模式。
4. 如需未 @ 接话，在配置中启用参与判断并选择 `block`，即 `participation.enabled: true`、`participation.mode: block`。`log` 只记录判断，不改变原入站规则；默认未启用。

昵称最多 8 个，每个 2–20 字。识别明确呼唤，如“鱼鱼，在吗”“鱼鱼你怎么看”，不会仅因一句话包含昵称就回应。昵称用于聊天模式的群参与判断，不要求加入免 @ 群列表；仍服从权限、暂停、安静时段及对其他人的提及/引用判断，不等同于平台 @。

活跃档位优先级：**本对话设置 → 人设默认 → 全局配置**。

| 档位 | 行为 |
|---|---|
| 安静 | 提高主动接话门槛，主动插话及跨轮表情冷却为基准的 2 倍 |
| 正常 | 使用全局门槛和冷却 |
| 活跃 | 降低主动接话门槛，主动插话及跨轮表情冷却为基准的一半 |
| 继承 | 使用人设或全局设置 |

档位不会开启已关闭的参与判断或图库，也不会绕过暂停、安静时段、日上限和同图去重。默认参与判断安静时段为 `23:00–08:00`。成功回复后，同一参与者在 120 秒内可自然续聊；成功接话刷新窗口，不消耗主动插话额度。

首条回复从收到输入起等待随机 1–3 秒，与模型生成重叠；生成已超过等待时间时不追加完整延迟。连续短消息会合并处理；普通回复默认不引用原消息。梗图优先用于接话，明确要求读字、翻译、解释或分析时正常回答。

人设生效顺序：当前模式绑定 → 旧对话提示词 → 默认人设 → 旧默认提示词。正文最多 4000 字，保存后下一回合生效；切人设或模式会取消尚未发送的旧回复。写旧式对话提示词会解除该对话两种模式的人设绑定。

## 表情与图文预演

聊天模式收到的图片进入本机图库，默认自动视觉打标。可编辑描述和用途标签、筛选「只看缺描述」、单张重新识别或每次补全最多 20 张。识别队列串行执行并显示进度；识别期间的人工修改会保留，已收藏图片不会自动移入回收站。

自动识别使用 `stickers.vision.provider` / `model`，默认 `deepseek-account / deepseek-flash`。图片会交给该模型并产生用量；可关闭 `stickers.vision.enabled`，或改为已配置的视觉模型。

精选优先参与选图，仍检查可见范围和额度。群图默认跨群共享；私聊图只对本私聊可见，`stickers.noShareGroups` 指定群的图片也不跨群，可关闭 `stickers.crossGroup`。默认每轮最多 2 张、跨轮冷却 30 秒、每个对话每日 30 张、同图 24 小时去重；活跃档位只调整冷却，已有配置作为基准。

人设编辑器的「隔离试聊 · 图文预演」支持未保存草稿、文字和单张 PNG / JPG / WebP（最多 2 MiB），也可选择图库图片。选择预演对话后，会按该对话的可见范围、精选、冷却和配额检查图文动作。浏览器可保存最多 10 个文字与图库编号样例，上传原图不存入样例。

预演调用一次所显示的模型，会消耗模型额度；不发送 QQ、不执行工具、不创建 QQ 会话、不修改人设，也不扣图库发送额度。它不包含宿主完整提示或真实群历史，实际群聊还受平台能力和上下文影响。

## 常用命令与权限

| 命令 | 用途 |
|---|---|
| `/qq-help`、`/qq-status`、`/qq-config` | 帮助、状态、配置入口 |
| `/qq-login`、`/qq-logout`、`/qq-reconnect` | 登录、断开、重连；个人 QQ 在 NapCat 登录 |
| `/qq-mode work\|chat` | 切换当前对话模式 |
| `/qq-persona list\|show\|use <id>\|clear` | 查看或切换当前模式人设 |
| `/qq-model`、`/qq-reasoning` | 查看或修改模型与推理强度 |
| `/qq-new`、`/qq-sessions`、`/qq-switch <序号>`、`/qq-title <标题>` | 会话管理 |
| `/qq-stop [--keep]` | 停止生成；默认清空待处理消息，`--keep` 保留队列 |
| `/qq-pref show\|name <称呼>\|pause <分钟>\|resume\|stickers on\|off` | 偏好、称呼、暂停主动互动、开关表情 |
| `/qq-sticker list\|keep\|trash\|restore\|tag\|send\|delete` | 查看或整理图库；参数见 `/qq-help` |
| `/qq-schedule list\|remove <id>` | 管理提醒；也可直接让模型设置提醒 |
| `/qq-approve <用户标识>` | 管理员批准私聊配对 |
| `/qq-requests`、`/qq-request <编号> allow\|deny` | 个人 QQ 好友/群请求处理 |

群聊默认向群成员开放，陌生私聊默认需配对批准。聊天、会话控制、模型控制和审批权限分别配置。没有消息按钮的线路通过回复 `approve` / `deny` 处理当前待审批请求。

渠道默认模型在配置页选择。优先级为对话中显式选择的模型 → `agentOptions` → DSH 全局默认。只有配好凭据的模型才能正常使用。

## 诊断、数据与更新生效

「聊天控制」展示最近消息的未被叫到、参与条件不足、安静时段、暂停、排队、模型生成、自然等待、发送结果或表情限制。最多保留 100 条内存记录，不记录正文和图片，重启清空。

完全没有入站记录时先看首页线路状态；已生成但未发出时查看发送失败原因及平台限制。`/qq-reconnect` 只重连当前配置，不加载升级后的代码。

控制台配置通过 DSH 配置服务保存并请求重载；缺少配置服务会提示。代码升级应重新加载插件或重启 DSH，页面修改刷新即可。

默认数据目录 `~/.dsh/qq-adapter/` 包括会话映射、人设、明确偏好、群笔记和图库。群记忆保存长期约定/称呼/梗，近期缓冲有大小上限，不是完整历史归档。备份时保存数据目录；凭据由 DSH 凭据服务独立管理。
